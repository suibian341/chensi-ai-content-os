# 视频剪辑服务上云服务器方案

本文用于客户选择 `chensi-video-render-service` 的云服务器配置。服务包含 AI 自动剪辑、口播去气口、行业高光剪辑三种模式，依赖 FFmpeg 和 faster-whisper 进行视频处理与语音识别。

## 方案一：低成本 CPU 版

### 推荐配置

| 项目 | 建议配置 |
|---|---|
| 云服务器 | 通用计算型或计算优化型 |
| CPU | 8 vCPU |
| 内存 | 16 GB |
| 系统盘 | 40 GB SSD |
| 数据盘 | 100 GB SSD/NVMe 起步 |
| GPU | 不需要 |
| 操作系统 | Ubuntu 22.04/24.04，x86_64 |
| 网络 | 10 Mbps 起步；素材上传较多时建议 20 Mbps |
| 队列并发 | 1 |

### 适用场景

- 每天处理量较少，通常不超过十几条视频。
- 客户可以接受单条视频等待时间较长。
- 以测试、试运行、小规模内部使用为主。
- 预算优先，暂时不购买 GPU。

### 性能预期

该方案可以运行完整服务，但 Whisper 语音识别使用 CPU，处理速度会明显慢于 GPU。视频输出还会经过 1080 级别、30fps 的 FFmpeg 转码，CPU 使用率可能长时间较高。

建议保持 `VIDEO_RENDER_QUEUE_CONCURRENCY=1`，不要同时运行多个渲染任务。若使用默认的 `large-v3` 模型，单条较长视频可能需要较长时间；如客户更重视速度，可将模型调整为 `medium` 或 `small`，但识别准确率会有所下降。

### 月度费用量级

约 **200～600 元/月**，具体取决于云厂商、地域、带宽、磁盘和包年包月折扣。该价格不包含对象存储、流量和备份费用。

### 优点

- 价格最低，适合先上线验证。
- 配置简单，不需要 NVIDIA 驱动和 CUDA 环境。
- 后续可以直接升级 CPU、内存或迁移到 GPU 机型。

### 局限

- Whisper 识别速度较慢。
- 不适合多个用户同时提交渲染任务。
- 长视频或高分辨率视频会占用较多 CPU 时间。

### 适合选择本方案的客户

如果当前业务量小、预算有限，且可以接受任务排队和较慢的处理速度，选择方案一即可。建议先以此方案运行一段时间，根据实际任务耗时和每日任务量再决定是否升级。

## 方案二：GPU 生产推荐版

### 推荐配置

| 项目 | 建议配置 |
|---|---|
| 云服务器 | GPU 计算型 |
| CPU | 8 vCPU |
| 内存 | 32 GB |
| GPU | NVIDIA T4 16 GB |
| 系统盘 | 50 GB SSD |
| 数据盘 | 200 GB SSD/NVMe 起步 |
| 操作系统 | Ubuntu 22.04/24.04，x86_64 |
| 网络 | 10～20 Mbps |
| 队列并发 | 1，后续根据监控调整 |

也可以使用 NVIDIA L4 24 GB。L4 性能更强，但价格通常更高；除非任务量已经稳定增加，否则 T4 的性价比更好。

### 适用场景

- 面向真实客户提供服务。
- 每天几十条视频，或多个用户会提交任务。
- 希望缩短 AI 语音识别等待时间。
- 默认使用 `faster-whisper-large-v3`，并保留较好的识别准确率。

### 性能预期

GPU 主要用于加速 faster-whisper 语音识别。FFmpeg 的缩放、字幕烧录、转场和 `libx264` 视频编码仍然主要消耗 CPU，因此不能只看 GPU 显存，8 vCPU 和 32 GB 内存也需要保留。

建议使用 CUDA + `float16`，并保持单任务并发。单张 T4 同时加载多个 Whisper 进程可能造成显存不足或性能下降。待监控确认显存和 CPU 余量后，再考虑将并发提高到 2。

### 月度费用量级

约 **1500～4000 元/月**，具体取决于云厂商、地域、GPU 机型、带宽、磁盘和计费方式。使用抢占式/竞价实例可以降低费用，但不建议作为唯一生产实例。

### 优点

- `large-v3` 语音识别速度明显快于 CPU 方案。
- 适合真实生产使用，用户等待体验更好。
- 仍然只需要一台服务器，部署和维护成本可控。
- T4 价格和性能比较均衡，后续可升级到 L4。

### 局限

- 月成本明显高于 CPU 方案。
- 需要安装 NVIDIA 驱动、CUDA 运行库和 NVIDIA Container Toolkit。
- 视频编码仍然受 CPU 性能影响，GPU 不会让所有步骤同比加速。

### 适合选择本方案的客户

如果服务需要对外提供、客户对等待时间有要求，或者预计每天有几十条任务，建议直接选择方案二。它是当前项目默认 `large-v3` 模型下更稳妥的生产起步配置。

## 两套方案对比

| 对比项 | 方案一：CPU 版 | 方案二：GPU 版 |
|---|---:|---:|
| 初期成本 | 低 | 中等 |
| 语音识别速度 | 较慢 | 较快 |
| 默认 large-v3 | 可以运行，但耗时较长 | 推荐 |
| 建议并发 | 1 | 1，监控后可尝试 2 |
| 部署复杂度 | 低 | 中等 |
| 适合环境 | 测试、小规模 | 正式生产 |
| 后续扩展 | 升级 CPU 或迁移 GPU | 升级 L4 或增加 Worker |

## 两套方案都需要的部署条件

1. 安装 FFmpeg、FFprobe、Python 和 faster-whisper。
2. `/models` 使用持久化磁盘，提前缓存 Whisper 模型，避免首次任务临时下载。
3. `/data` 使用持久化数据盘，保存上传素材、生成视频和背景音乐。
4. 生产环境建议使用 Nginx 或 Caddy 提供 HTTPS，不要直接把 4399 端口暴露到公网。
5. 当前任务队列和任务状态保存在服务进程内存中，服务重启后未完成任务可能丢失。
6. 当前单个素材最大约 2 GB，数据盘容量应按“原始素材 + 生成文件 + 临时文件 + 保留周期”规划。
7. 项目中的 API Key 只用于示例，正式部署前必须更换并妥善保存，不要提交到代码仓库。

## 最终建议

- **预算优先、先验证业务：选择方案一。**
- **正式对外提供服务、重视处理速度：选择方案二。**

如果暂时无法确定业务量，建议先购买方案二的 T4 实例，但将队列并发保持为 1。这样可以保留默认 `large-v3` 的识别质量，同时避免一开始投入更高规格的 GPU 服务器。

> 费用为市场常见区间，仅用于方案比较。最终价格以客户选定的云厂商、地域、带宽、磁盘、包年包月或按量计费方式为准。

## 可线上调用的替代方案

除了购买 GPU 云服务器，也可以调用第三方在线 API 或 Serverless GPU。需要注意：当前项目包含“语音识别 + 语义筛选 + 自动匹配素材 + FFmpeg 转场/字幕烧录”等定制逻辑，下面的服务大多不能直接替换当前代码，需要做一层适配或重写渲染流程。

### 方案 A：RunPod Serverless（适合保留现有代码）

RunPod Serverless 可以部署自定义 Docker 镜像，并通过 HTTP/API 按任务调用 GPU Worker。可以把当前项目中的 Whisper 和 FFmpeg 打包成 Worker，任务完成后把结果写回 OSS/S3/RunPod 网络存储。

- 官方价格页：<https://www.runpod.io/pricing>
- Serverless 24 GB GPU 档（包含 L4、A5000、3090 等）页面价格约 **0.69 美元/小时**，按秒计费。
- 专用 Pod 的 L4 页面价格约 **0.49 美元/小时**，适合持续运行的服务。
- 网络存储页面价格从约 **0.07 美元/GB/月** 起，具体以实时页面为准。

**优点：** 不需要长期租用 GPU，任务少时可以缩容到 0；支持自定义镜像，最接近当前项目的运行方式。

**需要改造：** 当前服务是普通 HTTP 服务，需要增加 RunPod Worker 入参/出参适配、任务状态回调、对象存储上传下载和超时重试。不能把现有 4399 端口原样当作 Serverless Endpoint 使用。

**建议：** 如果每天任务不稳定、偶尔有高峰，可优先评估 RunPod Serverless；如果每天持续有任务，专用 Pod 或国内 GPU 云主机通常更简单。

### 方案 B：Modal Serverless（适合技术团队）

Modal 支持用 Python 定义容器、GPU 和 HTTP/Web Function，可以将自定义 FFmpeg/Whisper 镜像部署为按请求启动的服务。

- 官方价格页：<https://modal.com/pricing>
- T4 约 **0.000164 美元/秒（约 0.59 美元/小时）**。
- L4 约 **0.000222 美元/秒（约 0.80 美元/小时）**。
- Starter 计划为 0 美元/月，并包含每月 30 美元计算额度；正式团队计划另计。

**优点：** Serverless、按实际运行时间计费，适合突发任务；容器和 API 编排能力较完整。

**需要改造：** 需要用 Modal 的 Python API 包装当前 Node 服务，或把渲染部分拆成独立 Worker；需要重新设计任务队列、文件存储和回调机制。

**注意：** Modal 页面显示不同区域可能有 1.15～1.75 倍价格系数，且海外网络、数据合规和跨境文件传输需要单独确认。

### 方案 C：Shotstack 视频编辑 API（适合模板化视频）

Shotstack 是托管式视频编辑 API，客户端提交 JSON 时间线，服务端完成素材拼接、字幕、叠加和转码并返回结果地址。

- 官方价格页：<https://shotstack.io/pricing/>
- 按量约 **0.30 美元/渲染分钟**，订阅方案约 **39 美元/月起，约 0.20 美元/分钟**。
- 官方页面标注支持 1080p、最长 3 小时渲染，并提供 API 和 Webhook 能力。

**适合：** 固定模板、字幕、片头片尾、贴纸、转场、商品视频等标准化生产。

**不适合直接替换当前服务的部分：** 项目中的 Whisper 词级时间戳、语义高光筛选、素材语义匹配和口播停顿检测属于自定义算法，不能仅通过 Shotstack JSON 原样复现。需要先在自己的服务中完成分析，再把最终时间线提交给 Shotstack。

### 方案 D：Creatomate 视频 API（适合模板和批量生成）

Creatomate 提供模板编辑器、API、批量数据源和 JavaScript Preview SDK，适合按照模板批量生成短视频。

- 官方价格页：<https://creatomate.com/pricing>
- 官方页面显示 Essential 年付约 **45 美元/月**，含 2,000 credits；提供 50 credits 免费试用。
- 官方说明：720p、25fps 视频约消耗 14 credits/分钟，1080p 会消耗更多 credits；生成文件通常托管最多 30 天。

**适合：** 固定版式、营销视频、社交媒体短视频、批量替换文字/图片/音频。

**限制：** 仍然不是当前项目的直接运行环境。需要把本地 FFmpeg pipeline 改写成模板和元素参数，语义剪辑部分仍需自建或另接 ASR/LLM 服务。

### 方案 E：国内云媒体处理 API（适合国内网络和合规）

#### 阿里云 MPS/IMS

- 官方页面：<https://www.aliyun.com/product/mps>
- 支持音视频转码、字幕压制、水印、工作流、AI_ASR 语音识别等能力，并提供 OpenAPI/异步任务接口。
- 官方页面示例通用转码包：50 分钟约 1.08 元、5,000 分钟约 87 元、20,000 分钟约 304 元；AI 能力、存储、流量等费用需按实际产品和地域确认。

#### 腾讯云 MPS

- 官方页面：<https://cloud.tencent.com/product/mps>
- 支持 API 任务、音视频转码、智能字幕、ASR/OCR、多语言字幕、增强和工作流编排。
- 官方页面展示普通转码包首购活动价格，最终价格需以地域、资源包和具体 AI 功能报价为准。

**适合：** 视频必须留在国内、需要国内对象存储和合规支持，或主要需求是转码、字幕、水印、增强。

**限制：** MPS 更像媒体处理基础设施，不会自动实现当前项目的三种定制剪辑逻辑。通常需要保留一个业务编排服务：负责上传、素材选择、语义分析和任务状态，再调用云媒体 API 完成转码或字幕处理。

## 线上方案如何与当前项目配合

| 目标 | 推荐方式 | 改造量 |
|---|---|---:|
| 完整保留当前三种剪辑逻辑 | 方案一/二自建 GPU，或 RunPod/Modal 自定义 Worker | 低～中 |
| 只想把 FFmpeg 转码外包 | 阿里云 MPS、腾讯云 MPS | 中 |
| 固定模板批量出片 | Shotstack 或 Creatomate | 中～高 |
| 只外包语音识别 | 国内 ASR/Paraformer 或其他 Speech-to-Text API | 中 |
| 任务量低且波动大 | RunPod Serverless 或 Modal | 中～高 |

## 线上调用的实际推荐

1. **最省改造：** 继续使用方案二的 GPU 云服务器，当前代码基本可以直接部署。
2. **低频、希望按量付费：** 将当前服务改造成 RunPod Serverless Worker，并把素材和结果放对象存储。
3. **国内合规优先：** 使用阿里云 MPS 或腾讯云 MPS 做转码/字幕，同时保留一个轻量业务服务处理语义剪辑逻辑。
4. **模板化生产：** 如果后续不再需要当前的语义高光和口播去气口算法，可以评估 Shotstack 或 Creatomate，接入速度会更快。

> 以上价格和功能来自各服务商公开页面，云厂商会根据地域、活动、套餐和 AI 功能调整价格。正式采购前应以官网实时报价及数据处理条款为准。

## 阿里云纯 CPU 方案如何购买

本项目的 CPU 方案适合使用阿里云 ECS 或轻量应用服务器。两者都能运行 Docker、FFmpeg 和 faster-whisper，但购买前需要同时考虑持续 CPU 负载、视频文件传输和后续扩容。

### 轻量应用服务器和 ECS 对比

| 项目 | 轻量应用服务器 | ECS 云服务器 |
|---|---|---|
| 价格 | 通常更低，带宽/流量常打包销售 | 单项计费，初始价格可能略高 |
| 带宽 | 套餐内固定带宽和流量包，简单 | 可单独选择固定带宽或按使用流量，调整更灵活 |
| CPU 持续渲染 | 可以运行，但需确认具体实例的 CPU 性能 | 更适合长期满载的 FFmpeg 任务，可选择计算优化型 |
| 磁盘 | 规格和扩容方式较受套餐限制 | 可单独增加 ESSD 数据盘，扩容更方便 |
| 网络能力 | 适合单机、低复杂度部署 | 支持 VPC、安全组、EIP、负载均衡和后续多机扩展 |
| 适合本项目的场景 | 测试、低频、小规模单机服务 | 正式对外服务、视频传输较多、需要长期维护 |

**结论：** 如果只是验证业务、每天任务不多且只需要一台机器，轻量应用服务器的性价比通常最高；如果要长期对外提供视频服务，建议直接选 ECS。视频剪辑会持续占用 CPU，并且后续很可能增加数据盘、带宽或 Worker，ECS 的可扩展性更适合正式环境。

### 推荐下单配置

#### 选择轻量应用服务器：低成本试运行

- 8 vCPU、16 GB 内存（如果所在地域没有该规格，至少选择 4 vCPU、16 GB，不建议 2 vCPU）。
- 系统盘按套餐提供；另配或预留至少 100 GB 数据空间。
- 10 Mbps 公网带宽起步。需要频繁上传 1～2 GB 视频时，选择 20 Mbps 更合适。
- 使用 Ubuntu 22.04/24.04，开放 80/443；4399 只允许 Nginx/Caddy 在本机转发，不直接暴露。
- 适合每天十几条以内、允许排队、先运行 1～3 个月观察数据的客户。

轻量套餐的优势是带宽和流量规则比较简单，但要特别确认套餐包含的月流量。视频下载会快速消耗流量包，超出后的价格或限速规则必须在购买页面确认。若套餐只有 5 Mbps，2 GB 文件理论上传/下载时间约 55 分钟，不建议作为主要生产带宽。

#### 选择 ECS：正式生产推荐

- 计算优化型或通用计算型，8 vCPU、16 GB 内存。
- 40～60 GB 系统盘，另配 100～200 GB ESSD 数据盘；模型、素材、输出和临时文件放数据盘。
- 配置 EIP，10 Mbps 固定带宽起步；上传下载频繁时配置 20 Mbps。
- 安全组只开放 80/443 和必要的 SSH 管理来源，应用端口 4399 仅监听内网或本机。
- 后续可以增加数据盘、升级 CPU，或把上传/输出迁移到 OSS。

如果视频量明显增加，建议让客户端通过 OSS 预签名地址上传和下载，ECS 只负责分析和渲染。当前代码默认使用本地 `runtime-data`，迁移 OSS 需要增加对象存储适配，不能仅在控制台勾选后立即生效。

### ECS 应该按量还是包月包年

| 使用情况 | 推荐计费 | 原因 |
|---|---|---|
| 只测试 7～14 天，尚未确定是否长期使用 | 按量付费 | 随时释放，避免先承诺长期费用 |
| 已确定每天运行、服务器基本 24 小时在线 | 包月 | 成本低于长期按量，仍保留调整灵活性 |
| 已确认至少稳定使用 6 个月以上 | 包年包月 | 通常折扣最好，适合固定生产实例 |
| 任务只在少数日期运行，其他时间可停机 | 按量付费并在不用时释放/停止 | 只有在真正停机且不保留公网资源时才有明显节省 |

**本项目的实际建议：**

1. 第一次部署可用 ECS 按量付费跑通 7～14 天，记录 CPU 使用率、单条视频耗时、每日视频数量和实际公网流量。
2. 如果确认每天都有任务并且实例需要持续在线，改为包月；预计半年以上稳定使用，再改包年包月。
3. 不建议把唯一生产实例长期按量付费，持续运行时通常比包月/包年贵，而且容易忽略公网 IP、磁盘和带宽的持续费用。
4. 不建议使用抢占式/竞价实例作为唯一生产机器。实例被回收时，当前内存队列中的任务可能中断或丢失。

### 带宽选择：固定带宽还是按使用流量

- **固定带宽：** 适合每天都有视频上传/下载，月度费用可预测。对本项目建议 10 Mbps 起步，素材传输较多时 20 Mbps。
- **按使用流量：** 适合低频测试或大部分时间没有请求。视频文件大小波动较大时，月度费用不容易预估，需要设置带宽上限和费用告警。
- **不要只看带宽峰值：** 10 Mbps 理论传输速度约 1.25 MB/s，2 GB 文件单次传输约 27 分钟；20 Mbps 约 14 分钟，实际还会受用户网络、TLS 和并发影响。
- **下载量较大时：** 优先评估 OSS 直传/直下载或 CDN，避免所有原始素材和成品都经过 ECS 公网带宽。OSS/CDN 会产生独立的存储和下行费用，应与 ECS 带宽一起比较总价。

### 最终下单建议

- **最低成本试运行：** 轻量应用服务器 8 vCPU/16 GB，套餐带宽至少 10 Mbps，按月购买；确认月流量包足够后再考虑包年。
- **更稳妥的正式方案：** ECS 8 vCPU/16 GB，100～200 GB ESSD 数据盘，EIP 10 Mbps 固定带宽，先按月购买。上传下载较多时把带宽改为 20 Mbps。
- **还没有业务数据：** ECS 按量付费运行 7～14 天做测试；测试通过后转包月，而不是长期按量。

综合价格、带宽和后续维护，**轻量应用服务器是小流量试运行的最低价选择，ECS 包月是这个视频服务正式上线时的综合性价比选择**。如果只能选一个长期方案，建议购买 ECS 包月，而不是轻量长期套餐或 ECS 长期按量。

### ECS 按流量和轻量 200 Mbps 怎么选

需要先确认轻量套餐页面的两个数字：

1. **峰值带宽**：例如 200 Mbps，表示网络端口允许达到的最高速度，不等于每月无限流量。
2. **每月流量包**：例如 200 GB、500 GB 或 1 TB。视频公网下载通常会消耗这个额度，超出后的计费或限速规则要单独确认。

ECS 的“按使用流量”则是按照实际公网下行流量计费，同时设置一个最大带宽上限。对本项目，最大带宽设置为 20～50 Mbps 通常已经够用，不需要为了视频服务设置 200 Mbps。200 Mbps 理论速度约 25 MB/s，但当前服务默认单任务队列，实际瓶颈更多在 CPU、Whisper 和 FFmpeg，而不是端口峰值。

| 情况 | 更合适的选择 |
|---|---|
| 每月公网下行低于约 100 GB，任务量不稳定 | ECS 按流量，最大带宽 20 Mbps 左右 |
| 每月公网下行约 100～300 GB，需要费用可预测 | ECS 固定带宽 10～20 Mbps，或比较轻量套餐的流量包总价 |
| 每天持续处理，成品经常被下载，超过 300 GB/月 | 不建议直接用 ECS 按流量；比较 ECS 固定带宽、轻量流量包和 OSS/CDN |
| 只是内部测试、很少下载成品 | 轻量 200 Mbps 套餐通常更省事，但确认流量包足够 |

计算流量时，至少估算“成品下载量 + 重复下载量”。例如每月 100 条成品、每条 1 GB，就是约 100 GB 公网下行；如果每条成品 2 GB，则约 200 GB。上传方向通常不是主要收费项，但最终以阿里云控制台当前地域和产品规则为准。

**针对本项目的建议：** 如果客户量还没有确定，优先购买 ECS 按流量并把最大带宽限制为 20 Mbps，运行一个月观察实际下行流量；如果每月稳定超过约 100～300 GB，再改成 ECS 固定 10～20 Mbps，或把素材和成品迁移到 OSS 后使用预签名地址下载。不要因为轻量标注“200 Mbps”就默认它一定比 ECS 更快或更便宜，必须把“月流量包、超额价格、实例价格、数据盘价格”合并比较。
